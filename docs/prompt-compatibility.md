# API 到网页对话上下文的兼容流程

本文描述当前 OpenAI Chat Completions 与 Responses 共用的请求处理路径。其他协议入口不在本分支提供。

## 模型与请求

模型列表只公开 `deepseek-flash`，上游使用 `default` 通道。默认启用思考，可通过请求中的 `thinking: false` 关闭。旧的 `deepseek-v4-*`、`-nothinking` 变体和模型别名不再解析。无效模型会在处理内嵌附件之前被拒绝。

请求首先归一化为 `StandardRequest`；上下文检查、文件处理、账号选择、工具调用、输出和用量统计由共享运行时执行。Chat 和 Responses 各自只负责转换输入与输出格式。

## 上下文文件

启用 `current_input_file` 且对话达到字符阈值时，普通用户、助手及工具消息合并成一个按角色标识的文本文件，文件名是随机生成的十六进制字符串。系统和开发者指令留在实时提示中；工具定义也留在实时提示中。实时用户提示要求模型依据已提供的历史回答最新问题。未开启该配置、没有可用用户文本或未达到阈值时使用普通文本提示。

生成的消息和工具调用格式使用 `::sys::`、`::user::`、`::asst::`、`::tc::` 等标记。模型输出由工具解析器转换成 OpenAI 工具调用；这属于文本适配，不是上游原生工具执行。

相同账号、模型通道与文本在同一进程内可复用上传结果 20 分钟，并发的相同上传会合并。缓存不跨实例、不跨重启；直接 token 如果没有账号标识不会使用此缓存。上下文预检对文件文本与实时提示一起估算 token，用于本地保护，不能保证上游接受相同长度。

## 账号和文件的归属

会话、PoW 和文件引用必须属于同一账号。上传、会话创建及 PoW 不会在底层隐式换号。上游明确返回账号受限时记录状态；只有在没有调用方提供的外部文件引用时，请求层才可切换托管账号，并为新账号重新上传生成的上下文文件。存在已有附件或文件 ID 时返回错误，由调用方处理；不会把旧账号的文件引用带到新账号。

上游明确报告禁言或封禁时，本实例暂时将托管账号移出可用池。返回中没有禁言到期时间时使用一小时后的本地重试时间，该时间不是上游承诺的解封时间。文件配置可保存状态；环境变量配置下状态和缓存只保存在当前实例，Vercel 重启或多实例时不共享。该处理不保证避免账号限制。

## 维护与验证

修改消息归一化、上下文文件、工具调用或完成请求组装时同步更新本文，并运行 `go test ./...`。相关回归包括私有上下文上传、受限账号处理、账号切换与附件归属、Chat/Responses 以及流式和非流式路径。真实上游能否成功还取决于账号状态和上游服务。

## 空输出排查

上游返回思考但没有可见答案时，服务返回 `upstream_empty_output`，使用 502 表示上游输出异常；这本身不能证明触发了限流。流式响应开始后，状态码在错误事件中返回。日志只记录上游事件类型和计数，便于区分缺少答案片段与解析异常，不记录内容或凭据。
